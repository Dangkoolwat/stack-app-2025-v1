# 해결 방안 제안

## 방안 1: 마지막 메뉴 삭제 및 권한 체크 로직 수정 (권장)
- 내용: 
    1. `entities-menu.vue`에서 문제가 된 `게시글 리소스 관리` 메뉴 삭제.
    2. `entities-menu.component.ts`의 `hasAnyAuthority` 구현을 `home.component.ts`와 동일하게 스토어 직접 참조 방식으로 변경하여 런타임 에러 해결.
    3. `login-form.component.ts`에서 로그인 성공 후 리다이렉션 로직이 정상 작동하는지 확인.
- 장점: 사용자의 요청을 직접적으로 수행하며, 근본적인 크래시 원인을 해결함.
- 리스크: 없음.

## 방안 2: 메뉴는 유지하되 로직만 수정
- 내용: 메뉴를 삭제하지 않고 `hasAnyAuthority` 로직만 수정하여 에러 해결.
- 단점: 사용자가 "마지막으로 추가된 메뉴 우선 삭제할 것"이라고 명시적으로 요청했으므로 요청에 반함.

## 선택 로그
방안 1을 선택함. 사용자의 명시적 요청을 따르면서 시스템 안정성을 회복하는 것이 최우선임.
