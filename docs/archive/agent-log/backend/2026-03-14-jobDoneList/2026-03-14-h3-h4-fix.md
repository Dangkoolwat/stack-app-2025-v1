## 수행 작업

### H-3: 파일 다운로드 스트리밍 전환

1. `StorageService` 인터페이스에 `loadAsStream(String)` 추상 메서드 추가
   - `loadAsResource(String)` default 구현에서 `loadAsStream()`을 내부 호출하여 하위 호환 유지
   - 각 구현체는 `loadAsStream()`만 구현하면 됨

2. `LocalDefaultFileStorageService` — `loadAsResource()` override 제거, `loadAsStream()` 추가  
   (`UrlResource.getInputStream()` 반환)

3. `ShareFileStorageService` — 동일 패턴 적용

4. `S3FileStorageService` — `loadAsResource()` override 제거, `loadAsStream()` 추가  
   (`S3Client.getObject()` 반환 — `ResponseInputStream`은 `InputStream` 구현체)

5. `OciFileStorageService` — `loadAsResource()` override 제거, `loadAsStream()` 추가  
   (`GetObjectResponse.getInputStream()` 반환)

6. `UploadResource` — `ResponseEntity<byte[]>` 3개 엔드포인트를 `ResponseEntity<StreamingResponseBody>`로 전환
   - `downloadFile`, `previewFile`, `downloadPrivateFile` 모두 `loadAsStream()`으로 InputStream을 열어 `OutputStream.transferTo()` 파이프
   - byte[] 전체 heap 로드 완전 제거

### H-4: JWT URI 쿼리 파라미터 비활성화

7. `SecurityJwtConfiguration` — `bearerTokenResolver.setAllowUriQueryParameter(true)` → `false`

### 테스트 파일 업데이트

8. `S3FileStorageServiceT` — `getObjectAsBytes` mock → `thenAnswer` + `ByteArrayInputStream` 방식
9. `OciFileStorageServiceT` — `loadAsResource_ShouldCallOciGetObject` → `loadAsStream_ShouldCallOciGetObject`, `InputStream` try-with-resources 도입

## 수정된 파일

| 파일 | 변경 내용 |
|------|-----------|
| `StorageService.java` | `loadAsStream()` 추가, `loadAsResource()` default 구현으로 전환 |
| `LocalDefaultFileStorageService.java` | `loadAsStream()` 구현, 중복 `loadAsResource()` 제거 |
| `ShareFileStorageService.java` | 동일 |
| `S3FileStorageService.java` | `loadAsStream()` 구현 (S3 SDK ResponseInputStream) |
| `OciFileStorageService.java` | `loadAsStream()` 구현 (OCI SDK InputStream) |
| `UploadResource.java` | 3개 엔드포인트 `StreamingResponseBody` 전환 |
| `SecurityJwtConfiguration.java` | `allowUriQueryParameter` = false |
| `S3FileStorageServiceT.java` | mock 방식 교체, `StorageService` 인터페이스 타입으로 업그레이드 |
| `OciFileStorageServiceT.java` | `loadAsStream` 기반 테스트로 교체 |

## Architecture Impact

- `StorageService` 인터페이스 public contract 변경 (`loadAsStream` 추가)
- `UploadResource` 응답 타입 변경: `byte[]` → `StreamingResponseBody` (HTTP API 계약 유지 — 클라이언트 영향 없음)
- 보안 계층: `BearerTokenResolver` 동작 변경 (URL 토큰 허용 제거)

## Security Impact

- H-4 해결: JWT가 URL/액세스 로그에 노출되는 위험 제거
- H-3: OOM으로 인한 서비스 가용성 위험 제거

## Risks

- H-4 부작용: 기존에 URL 쿼리 파라미터로 JWT를 전달하는 클라이언트(WebSocket, iframe, 파일 다운로드 직접 링크 등)가 있다면 403 응답을 받게 됨. 프론트엔드팀과 사용 현황 확인 필요.
- S3 테스트: `thenAnswer` 방식으로 `ByteArrayInputStream` 반환 시 S3 SDK `ResponseInputStream` 타입과 실제 동작이 다를 수 있음. 실제 S3 연동 테스트별도 수행 권장.
