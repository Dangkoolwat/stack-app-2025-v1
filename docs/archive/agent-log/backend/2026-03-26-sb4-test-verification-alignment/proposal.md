# 해결 방안 제안

## 선택한 방안

다음 네 가지를 묶어서 처리하는 방안을 선택했다.

1. `pom.xml`에 Failsafe를 추가해 `verify`에서 `*IT`가 실제 실행되도록 정리
2. Testcontainers 선언을 `ImportTestcontainers` 기반 공식 패턴으로 정렬
3. 대표 관리자 IT를 JWT Bearer 토큰 기반으로 전환
4. 테스트 계약 오해를 줄이기 위해 `AGENTS.md`, `docs/operations/testing-guideline.md`를 보강

선택 이유

- 빌드 계약, 테스트 인프라, 보안 검증, 문서 오해 방지를 한 번에 연결할 수 있다.
- 문서만 보완하는 것보다 실제 실행 가능한 작업물로 남는다.
- 전체 대규모 테스트 전환 전에 가장 핵심적인 불일치를 먼저 해결할 수 있다.

## 대안 1

문서만 고치고 코드는 건드리지 않는 방식

채택하지 않은 이유

- 실제 `verify` 실행 경로가 없으면 문제의 핵심이 남는다.

## 대안 2

모든 `@WithMockUser` 기반 IT를 한 번에 JWT 방식으로 전환하는 방식

채택하지 않은 이유

- 범위가 과도하게 커져 한 번의 수정으로 검증하기 어렵다.
- 우선은 대표 관리자 IT를 전환해 기준을 세우는 것이 더 안전하다.
