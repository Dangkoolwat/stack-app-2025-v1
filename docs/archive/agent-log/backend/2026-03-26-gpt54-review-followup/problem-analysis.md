# 문제 분석

## 문제 현상

Spring Boot 4 + JHipster 9 차용 마이그레이션 결과물에 대해 기존 분석 문서와 agent-log는 전반적으로 긍정적 결론을 제시하고 있다.

그러나 실제 저장소 상태를 대조하면 다음과 같은 불일치가 확인된다.

1. 통합 테스트 완료 보고와 현재 Maven 실행 경로가 정확히 맞지 않는다.
2. Testcontainers 선언 방식이 Spring Boot 공식 패턴과 완전히 일치한다고 보기 어렵다.
3. JWT 기반 통합 테스트 표준화가 완료되었다고 보기 어렵다.
4. 일부 보고 문서가 실제 파일 구조와 다르다.

## 재현

다음 항목을 확인했다.

- `pom.xml`의 surefire 설정에서 `**/*IT*` 제외
- `target/surefire-reports` 내 IT 리포트 부재
- `src/test/java/` 내 `@WithMockUser` 잔존
- `src/test/resources/logback.xml` 내 레거시 로거 참조 잔존
- 기존 final-report에 존재하지 않는 `application-test.yml` 언급

## 원인

주요 원인은 두 가지로 판단된다.

1. 마이그레이션 구현과 검증 계약이 분리되어 정리되지 않았다.
2. 문서가 목표 상태를 중심으로 작성되면서, 과도기 상태와 실제 실행 경로가 충분히 기록되지 않았다.

## 영향

- 후속 에이전트가 테스트 완료 범위를 잘못 이해할 수 있다.
- 통합 테스트 통과 여부를 과신한 채 추가 변경을 진행할 수 있다.
- 보안 테스트에서 실제 JWT 체인 회귀를 놓칠 수 있다.
- 문서 신뢰도가 떨어져 재작업 비용이 증가한다.
