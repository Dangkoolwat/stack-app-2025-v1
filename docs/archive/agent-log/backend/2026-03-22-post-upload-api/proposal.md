# Proposal

## 대안 1 (채택): 백엔드 전용 업로드 API 생성 및 소프트 삭제 + 퍼지(Purge) 아키텍처
- TOAST UI Editor 전용 이미지 단건 `POST` API 구성
- 클라이언트 오접근 및 취소 시 발생하는 에셋 스토리지 좀비 파일을 방지하기 위해 클라이언트는 즉시 [X]를 눌러 소프트 삭제(`is_deleted = true`)를 발동, 이후 관리자가 단번에 일괄 삭제(Batch/Purge API) 하여 스토리지 요금을 방어하는 이중 안전망 도입.
- 확장성과 Vue 3 일관성을 모두 충족시킬 최우선 방안.

## 대안 2: 마크다운 에디터 대신 HTML 인라인 Blob 컨버팅 저장
- 단점: 백엔드 스토리지 API는 필요 없으나 `Board` 내 Content 필드 용량이 수십 메가바이트로 커져 조회 성능(Read) 저하. 배제.
