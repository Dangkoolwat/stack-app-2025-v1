제안된 방안

방안 1. 캐시 상수 단일화 및 삭제된 코드 재사용 (복구)

- 캐시 명칭을 모든 서비스에서 상수(CacheNames)로 사용하도록 강제함.
- 중복 코드 발생 시 소프트 삭제된 데이터가 있다면 해당 레코드를 복구함.
- 장점: DB 유니크 제약 조건을 유지하면서 기존 행을 효율적으로 재사용 가능함.
- 단점: 예기치 않은 데이터 복구로 인한 혼란 가능성.

방안 2. 캐시 상수 단일화 및 중복 발생 시 사용자 안내 (차단) - 최종 선택

- CacheNames 상수 사용.
- 중복 코드 발생 시 소프트 삭제된 데이터가 있더라도 이를 사용자에게 알리고 다른 코드를 입력하도록 유도함.
- 장점: 로직이 명확하고 사용자가 데이터 상태를 인지할 수 있음.
- 단점: 사용자는 한 번 쓴 코드를 다시 쓰지 못함.

선택 이유

- 사용자가 복구가 아니라 UI 차원에서 사용불가라고 하고 다른 코드를 입력해야 한다고 명시적으로 요청함.
- DB 제약 조건 및 외래 키 참조 구조상 물리 삭제가 불가능하므로 차단 방식이 가장 안전함.
