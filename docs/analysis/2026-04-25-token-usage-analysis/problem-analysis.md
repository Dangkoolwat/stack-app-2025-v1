# 토큰 소비 분석 (Token Usage Analysis)

## 1. 개요
현재 프로젝트 설정 및 작업 방식에서 발생하는 토큰 소비 패턴을 분석합니다. 사용자가 느끼는 높은 토큰 소비의 원인을 파악하고 구조적인 요인을 식별합니다.

## 2. 주요 토큰 소비 요인

### 2.1 대규모 지침 세트 (AGENTS.md)
- **현황**: `AGENTS.md` 파일은 약 17.5KB로 매우 상세한 시니어 아키텍트급 규칙을 담고 있습니다.
- **영향**: 이 지침은 모든 대화 턴(Turn)마다 시스템 프롬프트 또는 사용자 규칙으로 포함되어 기본 컨텍스트 비용을 발생시킵니다.

### 2.2 고비용 워크플로우 (Tier-based Process)
- **현황**: 모든 작업에 대해 `Standard` 또는 `Critical` 티어를 적용하며, 이 과정에서 6개의 분석/계획 문서 생성을 강제합니다.
- **영향**: 문서 생성 자체에 토큰이 소비될 뿐만 아니라, 이전 단계의 문서를 참조하는 과정에서 컨텍스트가 누적됩니다.

### 2.3 엄격한 무결성 검사 (Surgical Precision & Read-Before-Write)
- **현황**: 코드를 수정하기 전 반드시 `cat`, `grep`, `ls` 등을 통해 연관 로직을 분석하도록 강제합니다.
- **영향**: 분석을 위해 읽어들이는 소스 코드의 양이 많아질수록 컨텍스트 윈도우가 빠르게 채워집니다. 특히 `Global Impact Review`는 전체 코드베이스 검색 결과를 컨텍스트에 포함시킵니다.

### 2.4 다수의 에이전트 스킬 (Skills)
- **현황**: 현재 9개의 스킬이 등록되어 있으며, 각각의 `SKILL.md`는 수 KB에서 16KB에 이릅니다.
- **영향**: 에이전트가 필요에 따라 스킬을 읽어들일 때마다 추가적인 토큰이 소비됩니다.

### 2.5 누적된 에이전트 로그 (Agent Logs)
- **현황**: `docs/frontend/agent-log/` 및 `docs/backend/agent-log/` 하위에 수십 개의 작업 로그가 존재합니다.
- **영향**: 컨텍스트 검색(RAG) 또는 명시적 참조 시 과거의 상세 로그들이 포함되어 토큰 사용량을 가중시킵니다.

## 3. 결론
이 프로젝트는 **무결성(Integrity)과 품질(Quality)을 위해 효율성(Efficiency)을 희생한 구조**입니다. 시니어 아키텍트 수준의 정밀한 작업을 보장하기 위해 설계된 엄격한 규칙들이 역설적으로 높은 토큰 소비의 주원인이 되고 있습니다.
