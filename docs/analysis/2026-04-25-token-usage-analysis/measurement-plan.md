# 토큰 계측 계획

## 목적
토큰 절감 효과를 감이 아니라 기록으로 판단하기 위한 최소 계측 항목을 정의합니다.

## 기록 기준
각 작업마다 아래 항목만 짧게 남깁니다.

1. 작업 유형
   - 예: `docs`, `fix`, `review`

2. 사전 참조 파일
   - 실제로 읽은 핵심 파일만 적습니다.
   - 예: `AGENTS.md`, 관련 `docs/analysis`, 관련 코드 파일

3. 참조 범위
   - 대략적인 규모만 적습니다.
   - 예: `3 files / 1,200 lines`

4. 추가 컨텍스트
   - `graphify` 사용 여부
   - `archive` 참조 여부
   - 스킬 사용 여부

5. 결과 요약
   - 무엇이 줄었는지 한 줄로 적습니다.
   - 예: `AGENTS.md 대신 docs/standards 2개만 참조`

## 권장 로그 형식
아래 형식을 `task-log.md` 또는 `final-report.md`에 붙여 넣습니다.

```md
## Token Check
- 작업 유형:
- 사전 참조 파일:
- 참조 범위:
- 추가 컨텍스트:
- 결과 요약:
```

## 판단 기준
- `AGENTS.md`와 직접 연결된 참조가 줄면 성공입니다.
- `graphify`가 필요 없는 작업에서 생략되면 성공입니다.
- 오래된 `analysis` 대신 `archive` 또는 `KI`만 보면 성공입니다.

## 주의점
- 숫자를 정확히 못 세더라도 대략값으로 적습니다.
- 과도한 상세 로그는 남기지 않습니다.
- 새 규칙을 늘리는 것이 아니라, 기존 작업의 비용을 보이게 만드는 것이 목표입니다.
