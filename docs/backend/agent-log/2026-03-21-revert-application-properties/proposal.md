# 방안 제시

## 후보 1: ApplicationProperties 중첩 클래스 원복 (선택됨)
### 설명
기존에 분리되었던 8개의 개별 Properties 파일(`RedisProperties`, `FileProperties` 등)을 삭제하고, `ApplicationProperties.java` 내부에 `static class` 구조로 통합합니다.

### 장점
- 설정 의존성 관리의 단순화.
- IDE의 자동 완성 및 설정값 탐색 용이성 증대.
- JHipster 등 표준 프레임워크 관례에 부합.

### 리스크
- 통합 파일의 라인 수가 길어질 수 있으나, 현재 규모(약 150~200라인)에서는 관리 가능한 수준임.

## 후보 2: 개별 파일 유지 및 인터페이스 통일
### 설명
현재의 분리된 구조를 유지하되, 공통 인터페이스를 통해 경로 및 설정 접근 방식을 통일합니다.

### 단점
- 구조적인 복잡성이 여전히 존재하며, 사용자가 비추천한 방식임.
- 의존성 주입 코드가 늘어남.

## 선택 이유
사용자의 명확한 요구사항("디펜던시 작업이 너무 많아 비추임, 원복하여 고려")을 우선적으로 반영하며, 시스템의 설정 응집도를 높이기 위해 후보 1을 선택함.
