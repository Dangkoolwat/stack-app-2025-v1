## 개요 (Summary)
- 데이터 생성 시 고유 제약 조건 위반을 발생시키던 원인을 제거하고, 엔지니어의 통찰력에 따라 데이터베이스 시퀀스 패턴을 올바르게 위임하도록 구조를 탈바꿈했습니다.

## 이유 (Reason)
- Liquibase에서 초기 데이터들을 넣을 때 1, 2, 3.. 과 같이 ID를 하드코딩해서 넣었는데, 정작 백엔드 JPA를 관장하는 시퀀스는 1번부터 시작하도록 선언되어 있었습니다. 이 때문에 백엔드가 시퀀스를 호출하면 이미 사용된 번호를 발급받게 되면서 충돌이 발현되었습니다. 초기 데이터에도 하드코딩된 값을 제거하고 시퀀스의 `nextval`에 위임하는 것이 맞습니다.

## 영향 (Impact)
- 초기 데이터 인서트와 애플리케이션 시퀀스 할당 간의 완벽한 징검다리 복원: 로컬 데이터 리셋 시 초기 데이터들이 1부터 ID를 부여받고, 애플리케이션에서는 곧장 그 다음 번호를 이어받아 제약 조건 위반이 근절됩니다.

## 결과 및 대응법 가이드 (Results)
- 샘플 데이터 21건의 INSERT 구문에서 `id` 컬럼을 `valueSequenceNext="common_detail_sequence_generator"`로 모두 치환했습니다.
- `common_detail_sequence_generator`의 최초 시작값은 `1`로 정상화되었습니다.
- 계획대로 로컬 데이터/초기화를 진행(`리셋`)해 주시면 완벽하게 적용됩니다.
