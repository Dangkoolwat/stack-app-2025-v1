# 문제 분석 (Problem Analysis)

## 현상 및 배경
- 기존 HikariCP 설정이 고정된 'Magic Number' (예: `maximum-pool-size: 10`)로 하드코딩되어 있어, 실제 운영 서버의 하드웨어 스펙(CPU 코어 수 등)을 유연하게 반영하지 못함.
- 개발, 운영 장비의 스펙 차이가 있음에도 일관된 풀 사이즈를 사용하여 리소스 낭비 또는 트래픽 병목의 원인이 될 수 있음.

## 재현 / 문제점
- 서버를 스케일업(Scale-up)하여도 DB 커넥션 풀이 늘어나지 않음.
- HikariCP 공식 권장사항(CPU 권장 계산식 및 고정 풀 설정)이 반영되지 않아 성능 최적화 미흡.
