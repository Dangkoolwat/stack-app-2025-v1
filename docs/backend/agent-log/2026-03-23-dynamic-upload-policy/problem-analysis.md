# 문제 분석 (Problem Analysis)

## 현상
- 현재 프로젝트의 파일 업로드 정책이 `ApplicationProperties` 기반의 정적 배열 구조로 되어 있어, 운영 환경에서 설정을 변경하려면 서버를 재시작해야 함.
- 파일 확장자만 검사하고 있어, 확장자 위조(MIME Spoofing) 공격에 취약함.
- 관리자 UI에서 파일 업로드 제한(용량, 타입 등)을 동적으로 제어할 수 있는 기능이 부재함.
- ArchUnit 테스트 결과, 도메인 레이어에서 서비스 레이어 DTO를 참조하는 아키텍처 위반 사항이 발견됨.

## 원인
- 기존 설계가 정적 설정 파일 기반으로 되어 있어 유연성이 부족함.
- `Settings` 엔티티가 `com.daangcool.stack.service.dto` 패키지의 클래스를 직접 참조하고 있음.

## 영향
- 운영 효율성 저하 (설정 변경 시마다 배포/재시작 필요).
- 보안 리스크 (악성 파일 업로드 가능성).
- 아키텍처 정합성 훼손으로 인한 유지보수 어려움.
