# 해결 방안 제안 (Proposal)

## 방안 1: JSON 기반 동적 정책 관리 (선택됨)
- **내용**: `Settings` 엔티티의 `global_settings` 필드를 활용하여 JSON 형태로 정책을 저장하고, `UploadService`에서 이를 동적으로 읽어 검증함.
- **장점**: 스키마 변경 없이 유연한 확장 가능, 실시간 반영.
- **리스크**: JSON 파싱 성능 오버헤드 (캐싱으로 해결 가능).

## 방안 2: 별도 정책 테이블 구축
- **내용**: `FilePolicy`라는 별도의 엔티티와 테이블을 생성하여 관리.
- **장점**: RDB의 제약 조건을 활용한 데이터 무결성 보장.
- **단점**: 구조 변경 시마다 DDL 발생, 관리 포인트 증가.

## 선택 이유
- 프로젝트의 기존 `Settings` 구조가 JSON 통합 방식을 선호하고 있으며, 정책의 복잡도가 테이블로 분리할 만큼 크지 않으므로 방안 1이 더 효율적임.

## 리스크 및 대책
- **성능**: 자주 조회되는 설정이므로 `Settings` 조회 시 캐싱을 적용함.
- **아키텍처**: 위반 사항 해결을 위해 핵심 모델을 `domain.vo` 패키지로 이동함.
