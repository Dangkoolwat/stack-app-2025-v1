# 해결 방안 제안 (Proposal)

## 방안 1: 초기 스키마 변경 및 마이그레이션 고도화 (선택됨)
- 내용: 
    - `20251005203000_added_entity_Settings.xml` (초기 스키마)에서 `global_settings` 타입을 처음부터 `clob`으로 변경.
    - 기존 사용자를 위해 Oracle 전용 안전 마이그레이션 스크립트 작성 (임시 컬럼 생성 -> 데이터 복사 -> 컬럼 삭제 -> 이름 변경).
    - `FileTypePolicy`의 기본 타입을 래퍼 클래스(`Boolean`, `Long`, `Integer`)로 변경하여 유연한 역직렬화 지원.
- 장점: 모든 데이터베이스 환경에서 테스트 통과 및 운영 안정성 확보.
- 단점: 마이그레이션 스크립트가 다소 복잡해짐.

## 방안 2: 데이터 축소
- 내용: 템플릿 데이터를 삭제하거나 최소화하여 `VARCHAR2(2000)` 내에 맞춤.
- 장점: 스키마 변경이 필요 없음.
- 단점: 사용자가 요구한 템플릿 기능을 충분히 제공할 수 없어 요구사항 미충족.

## 선택 이유
- Oracle XE 테스트 환경 및 운영 환경에서의 호환성을 완벽히 해결하면서, 사용자가 요청한 대량의 기본 템플릿을 안전하게 저장하기 위해 방안 1을 선택함.
